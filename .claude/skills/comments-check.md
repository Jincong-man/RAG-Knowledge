# comments-check

> RAG电商知识库问答系统 — 代码注释检查技能

## 功能概述

| 检查项 | 说明 | 触发词 |
|--------|------|--------|
| **注释覆盖率** | Python函数docstring、Vue组件注释是否完整，目标 **20%注释率** | "检查注释"、"注释够不够" |
| **注释匹配度** | 注释内容是否与代码实际逻辑一致 | "注释对不对"、"注释匹配" |
| **新手可读性** | 注释是否通俗易懂，术语是否解释 | "注释好不好懂" |

---

## 检查流程

### 第一步：注释覆盖率检查（数量）

#### Python文件注释统计

统计以下注释类型：
- `#` 单行注释
- `"""..."""` docstring（函数/类/模块级别）
- `'''...'''` 单引号docstring

**必须加注释的位置**：

| 位置 | 说明 | 示例 |
|------|------|------|
| 每个函数/方法 | docstring说明参数和返回值 | `"""获取指定用户的会话列表"""` |
| 每个类 | 类的用途说明 | `"""RAG问答链封装"""` |
| 每个路由 | API接口说明 | `"""SSE流式问答接口"""` |
| 复杂算法 | 步骤拆解 | `# 余弦相似度计算: cos(a,b) = a·b / (|a|*|b|)` |
| 配置项 | 用途解释 | `# 检索返回最相似的10个文档块` |

#### Vue文件注释统计

| 位置 | 说明 |
|------|------|
| `<script setup>` 顶部 | 组件用途说明 |
| 每个函数/action | 作用说明 |
| 每个computed | 计算逻辑说明 |
| 模板重要区块 | `<!-- 会话列表区域 -->` |

**目标比例：20%**（每10行中约2行注释）

---

### 第二步：注释匹配度检查（质量）

对每条注释逐一核对：

1. **读注释 → 看代码**：注释说做X，代码是否真的在做X？
2. **读代码 → 看注释**：代码逻辑，注释有没有描述准确？
3. **检查过期注释**：代码改过了但注释没更新？

常见问题：

```
❌ 注释说"返回用户列表"，但代码返回的是会话列表
❌ docstring说"async函数"，但函数定义没有async
❌ 注释说"使用Redis缓存"，但代码已经改为内存缓存
✅ 注释准确描述函数做了什么，包括边界情况
```

---

### 第三步：新手可读性检查（视角）

以"计算机新人学生"的视角阅读每条注释：

| 检查项 | 说明 |
|--------|------|
| **RAG术语解释** | 出现"embedding"、"向量检索"、"rerank"时是否解释 |
| **LangChain术语** | 出现"LCEL"、"Runnable"、"astream_events"时是否解释 |
| **FastAPI术语** | 出现"依赖注入"、"中间件"、"SSE"时是否解释 |
| **是否跳步骤** | 注释假设读者已知道某个前提 |
| **是否给出"为什么"** | 不只说"做了什么"，还说"为什么这么做" |

对比示例：

```
❌ "使用 bge-m3 做 embedding"
✅ "使用 bge-m3 模型将文本转换为向量（embedding：将文字转化为计算机能比较相似度的数字序列）"

❌ "LCEL chain 组装"
✅ "使用 LangChain 表达式语言（LCEL：一种用 | 管道符把处理步骤串起来的方式）组装RAG链"

❌ "SSE 流式输出"
✅ "使用 SSE（Server-Sent Events：服务器向浏览器持续推送数据的技术）实现逐字输出效果"
```

## 适用范围

| 目录 | 文件类型 | 检查维度 |
|------|----------|----------|
| backend/app/**/*.py | Python后端 | 覆盖率、匹配度、可读性 |
| frontend/src/**/*.vue | Vue组件 | 覆盖率、匹配度、可读性 |
| frontend/src/**/*.js | JavaScript | 覆盖率、匹配度、可读性 |

**排除**：`node_modules/`、`.venv/`、`__pycache__/`、`tests/`

## 输出格式

```markdown
## 📊 注释检查报告 — [文件名]

### 注释覆盖率：X%
- 总有效行：XXX
- 注释行：XX
- ⚠️ 未达到 20% 目标

### 🔴 缺少注释的位置
| 行号 | 问题 | 建议 |
|------|------|------|

### 🟡 注释不匹配
| 行号 | 问题 | 现有注释 | 建议修改为 |
|------|------|----------|------------|

### 🟢 新手不易读懂的注释
| 行号 | 问题 | 现有注释 | 改进建议 |
|------|------|----------|----------|
```

---

## 工作约定

1. **先统计后细查**：先算出整体覆盖率，再逐条检查质量和可读性
2. **不修改代码**：只输出报告和建议
3. **优先级排序**：先报缺少注释的，再报注释写错的，最后报写得不够好的
4. **给出具体建议**：每条问题给出改进后的注释版本
5. **按文件分别报告**：每个文件一份报告
