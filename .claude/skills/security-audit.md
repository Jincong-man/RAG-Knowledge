# security-audit

> RAG电商知识库问答系统 — 代码安全审计技能

## 功能概述

这个技能对项目代码进行安全审计，从以下四个维度检查：

| 检查项 | 说明 | 触发词 |
|--------|------|--------|
| **敏感信息泄露** | API Key、JWT Secret、数据库密码是否硬编码 | "查敏感信息"、"有没有密码泄露" |
| **注入漏洞** | SQL注入、XSS、Prompt注入风险 | "查注入漏洞"、"有没有XSS风险" |
| **明文配置** | `.env`、配置文件中的密钥是否明文存储 | "配置文件安全"、"明文密码" |
| **综合审计** | 以上全部 + 认证安全、传输安全、依赖安全 | "安全审计"、"安全检查" |

---

## 检查流程

### 一、敏感信息硬编码检查 🔴

| 检查项 | 搜索模式 | 风险等级 |
|--------|----------|----------|
| **API Key硬编码** | `sk-`、`api_key=`、`DASHSCOPE_API_KEY` 后跟真实值 | 🔴 严重 |
| **JWT Secret硬编码** | `JWT_SECRET_KEY` 后跟非占位符值 | 🔴 严重 |
| **数据库连接串** | `sqlite:///`、`mysql://`、`postgres://` 含密码 | 🔴 严重 |
| **邮箱/手机号** | `@xxx.com` 格式、连续11位数字 | 🟡 中等 |
| **内网地址** | `192.168.`、`10.0.`、`172.16.` | 🟡 中等 |

**重点检查文件**：`backend/.env`、`backend/app/config.py`

---

### 二、注入漏洞检查 🔴

#### SQL注入

| 检查项 | 说明 |
|--------|------|
| **原始SQL拼接** | 是否有`f"SELECT...{user_input}"`或`"..." + input` |
| **ORM安全使用** | SQLAlchemy查询是否使用参数化而非字符串拼接 |

#### XSS（跨站脚本攻击）

| 检查项 | 说明 |
|--------|------|
| **v-html指令** | Vue中是否直接渲染未消毒的HTML |
| **innerHTML** | 是否有`innerHTML = userInput` |
| **Markdown渲染** | markdown-it渲染是否开启了HTML过滤 |

#### Prompt注入（RAG系统特有）

| 检查项 | 说明 |
|--------|------|
| **用户输入未过滤** | 用户消息是否直接拼入system prompt |
| **知识库内容注入** | 知识库文档是否可能包含恶意prompt指令 |

---

### 三、配置文件明文存储检查 🟡

| 文件 | 检查重点 |
|------|----------|
| `backend/.env` | 是否存在且是否被`.gitignore`排除 |
| `backend/.env.example` | 是否包含真实密钥（应只有占位符） |
| `frontend/vite.config.js` | 是否硬编码了后端地址或密钥 |
| `.claude/settings.json` | 是否包含token、个人路径 |

---

### 四、其他安全隐患

#### 认证安全

| 检查项 | 说明 | 风险 |
|--------|------|------|
| **JWT过期时间** | access_token过期时间是否合理（建议≤24h） | 🟡 |
| **refresh_token策略** | 是否有过期和轮换机制 | 🟡 |
| **密码哈希** | 是否使用bcrypt等安全哈希算法 | 🔴 |
| **默认管理员** | jincong/123456是否应在首次登录后强制修改 | 🟡 |
| **频率限制** | 登录接口是否有暴力破解防护 | 🟡 |

#### API安全

| 检查项 | 说明 | 风险 |
|--------|------|------|
| **CORS配置** | `allow_origins=["*"]`是否过于宽松 | 🟡 |
| **文件上传校验** | 是否检查文件类型、大小、内容 | 🔴 |
| **权限校验** | 管理员接口是否有`require_admin`保护 | 🔴 |
| **输入校验** | Pydantic schema是否有长度/格式限制 | 🟡 |

#### 存储安全

| 检查项 | 说明 | 风险 |
|--------|------|------|
| **localStorage存token** | XSS攻击可读取，建议httpOnly cookie | 🟡 |
| **localStorage存用户信息** | 是否存储了不必要的敏感数据 | 🟡 |

## 输出格式

```markdown
## 🔒 安全审计报告 — [文件名]

### 🔴 严重风险（需立即修复）
| # | 问题类型 | 行号 | 问题描述 | 修复建议 |
|---|----------|------|----------|----------|

### 🟡 中等风险（建议尽快修复）
| # | 问题类型 | 行号 | 问题描述 | 修复建议 |
|---|----------|------|----------|----------|

### 🟢 安全建议（加固项）
| # | 建议类型 | 说明 | 改进方向 |
|---|----------|------|----------|

### 📊 审计统计
- 检查文件：X 个
- 🔴 严重风险：X 项
- 🟡 中等风险：X 项
- 🟢 安全建议：X 项
```

---

## 工作约定

1. **不修改代码**：只输出报告和建议，不直接改动源文件
2. **解释风险**：每条问题解释"为什么这是问题"和"攻击者会怎么做"
3. **给出可操作的修复方案**：每条建议附带具体的代码修改示例
4. **严重优先**：先报严重风险（🔴），再报中等（🟡），最后是加固建议（🟢）
5. **排除无关文件**：`node_modules/`、`.venv/`、`__pycache__/`、`chroma_data/` 不纳入检查
